## 2. 给主管1号的 system prompt 片段（漏召回对策，必须注入）

```text
你接入了长期记忆系统（MCP 工具：wake / recall / record / consolidate），规则如下：

1. 开始处理某个客户的沟通前，必须先调用 wake(subject_id=该客户id)，恢复这个客户的历史脉络。
2. 对话中涉及该客户的历史偏好、过往事件、之前说过的内容时，先调用 recall 再回答；不确定时宁可调用一次。
3. 对话中出现值得长期记住的事实时调用 record：
   - content 写成一句话、可脱离上下文独立理解；
   - type：preference=客户偏好/事实，event=情景/事件，constraint=长期约束；
   - importance：10=长期约束，7-9=重要事实/重大决定，4-6=一般事件，1-3=琐碎；
   - 不要记录寒暄、一次性信息、可随时重新查询的内容。
4. 一个客户的记忆绝不会出现在其他客户的召回结果里；不要跨客户引用记忆。
5. record 返回 dedup=merged 是正常现象（与已有记忆语义合并），无需重试。
```

## 3. 典型工作节奏

```
接收到客户X的新沟通
  → wake(subject_id="customer_x")            # 恢复脉络（≤1500 token）
  → 处理对话…（需要历史时 recall）
  → record(subject_id="customer_x", …) ×N    # 沉淀新事实
每日凌晨（cron）
  → consolidate(mode="all")                  # 对全部客户: 补向量/去重/归档
```

## 4. 记忆查看与人工干预

本地 PWA 面板：`cd external-memory/pwa && npm run dev` → http://localhost:5173
顶部 subject 切换器可切到任意客户视角，查看/编辑/删除该客户的记忆，支持导出 JSON。

## 5. 接入验收标准（与技术设计 §8 步骤 6 对齐）

- [ ] 主管1号处理客户 A 前主动 wake，且回答中体现了客户 A 的历史脉络
- [ ] 主管1号在对话中主动 record 了 ≥1 条新事实，importance 打分合理
- [ ] 询问客户 B 时 recall 结果不含客户 A 的任何内容
- [ ] PWA 里能看到两个客户各自的记忆，编辑后立即对召回生效
