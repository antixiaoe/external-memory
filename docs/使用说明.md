# 外部记忆库 MCP · 使用说明

> 一句话：给你的 Agent 装上长期记忆。会话开始「唤醒」、聊天中「回忆」、有值得记的事「记录」、定期「整理」——跨会话记住你和你的客户。
>
> 维护人：刘晓燚 · 问题反馈：直接找我 / 提 cwiki 评论

---

## 0. 两种用法，先选对

- **自托管（推荐个人）**：安装 MCP 后按[自托管教程](./自托管教程.md)配置**自己的四个凭据**（Supabase URL / Secret Key / 数据库密码 / 硅基流动 Key），后端是你自己的免费项目，数据完全归你。本文档 §2 之后的工具用法完全一致。
- **托管版（团队/agent）**：直接用部署好的共享端点，token 找维护人领。继续往下读。

## 1. 这是什么

一个托管在 Supabase 上的远程 MCP 服务，为 Agent 提供**持久化长期记忆**能力：

- 记忆不塞进上下文，按需召回，不随会话结束丢失
- 每条记忆带显著性打分（重要性 × 时间衰减 × 命中巩固），越重要、越常用的记忆越容易被召回
- 中文混合检索：向量语义（bge-m3）+ 关键词（pg_trgm）双路加权
- **多主体隔离**：每个用户 / 每个客户是独立的记忆空间，互不可见

## 2. 接入信息

| 项 | 值 |
|---|---|
| Endpoint | `https://bnxgezelwdztzhzrkugv.supabase.co/functions/v1/mcp` |
| Transport | Streamable HTTP（标准 MCP，POST JSON-RPC） |
| 鉴权 | `Authorization: Bearer <你的 token>` |
| Token 申请 | 找维护人领取，每人/每个 agent 一把独立 token |
| 可用工具 | `wake` `recall` `record` `consolidate` |

### Claude Code 配置

```json
{
  "mcpServers": {
    "external-memory": {
      "type": "http",
      "url": "https://bnxgezelwdztzhzrkugv.supabase.co/functions/v1/mcp",
      "headers": { "Authorization": "Bearer <你的 token>" }
    }
  }
}
```

### Cursor / 其他 MCP client

同上：类型选 HTTP（streamable），填 URL + Authorization header 即可。

## 3. 工具一览

### wake — 唤醒（会话开始时调一次）

恢复该主体的核心画像 + 最重要记忆（含全部长期约束）+ 进行中的事件脉络。

```jsonc
// 入参（人类用户的 token 无需任何参数）
{}
// agent token 必须指定主体
{ "subject_id": "customer_001" }
```

### recall — 回忆（按需）

```jsonc
{
  "query": "客户上次关于预算说了什么",   // 必填
  "top_k": 5,                          // 默认 5，最大 20
  "subject_id": "customer_001",        // 仅 agent token 必传
  "keyword_boost": true                // 默认 true；含人名/编号时保持开启
}
// 返回：记忆内容 + 加权分数 + 原文溯源
```

### record — 记录（出现值得长期记住的事实时）

```jsonc
{
  "content": "客户预算上限 50 万",       // 一句话、可独立理解
  "type": "preference",                // preference 偏好 | event 事件 | constraint 长期约束
  "importance": 8,                     // 10=长期约束 7-9=重要 4-6=一般 1-3=可丢弃
  "subject_id": "customer_001"         // 仅 agent token 必传
}
// 返回 dedup=created 或 merged（与已有记忆语义重复时自动合并，属正常现象）
```

**不要 record**：寒暄、一次性信息、可随时重新查询的内容。

### consolidate — 整理（定期维护，cron 或手动）

```jsonc
{ "mode": "all" }  // backfill 补向量 | merge 去重 | archive 归档 | all
// agent 不传 subject_id 时整理其授权范围内全部主体
```

## 4. 使用规约（建议写进你的 Agent 的 system prompt）

```text
1. 会话开始先调用 wake 恢复记忆脉络。
2. 涉及该用户/客户的历史偏好、过往事件时，先 recall 再回答；不确定时宁可调一次。
3. 出现值得长期记住的事实时调用 record，按 importance 规则打分；dedup=merged 无需重试。
4. 不要跨主体引用记忆——每个用户/客户的空间完全隔离。
```

## 5. 身份与隔离模型（重要）

- **token 即身份**：你能访问谁的记忆由你的 token 决定，模型无法通过参数伪造。
- 人类 token：只能读写自己的记忆空间（传 `subject_id` 也会被忽略）。
- Agent token：必须在每次调用传 `subject_id`（如 customer_id），且只能在授权白名单内。
- 客户 A 的记忆永远不会出现在客户 B 的召回结果里。

## 6. 人工管理面板（PWA）

本地运行（需要维护人提供的本地 env）：

```bash
cd external-memory/pwa && npm install && npm run dev
# → http://localhost:5173
```

可查看/编辑/删除任意你有权限的主体的记忆、管理 Story、粘贴原始素材提炼记忆、导出 JSON。

## 7. FAQ

**Q：record 返回 merged 是失败吗？**
不是。新内容与已有记忆语义重复（cosine > 0.9）时自动合并，重要性取更高者。

**Q：刚 record 的记忆 recall 不到？**
Embedding 是实时生成的，正常立即可召回；若 embedding 服务抖动会异步补齐（consolidate backfill），稍后再试。

**Q：记忆会无限膨胀吗？**
不会。低价值（importance≤2）、90 天未被命中、从未被强化的记忆会被 consolidate 归档；重复记忆会被合并。

**Q：误删/误记怎么办？**
PWA 面板可编辑、归档、硬删；归档的记忆可恢复，硬删不可恢复。

**Q：我的 token 泄露了？**
立即联系维护人吊销重发（改一行 OP_TOKENS 即生效）。
