# 外部记忆库 MCP · 自托管教程（四个凭据，15 分钟）

> 适合谁：想给自己的 Agent 配长期记忆、且**数据完全归自己管**的同事。
> 模式：MCP 服务跑在你本机（单文件、零依赖），后端是你自己的免费 Supabase 项目，embedding 用你自己的硅基流动免费额度。全程不依赖任何他人服务。

## 你需要准备的四个凭据

| # | 凭据 | 从哪拿 | 用途 |
|---|---|---|---|
| 1 | **Supabase Project URL** | supabase.com 建项目后可见 | 记忆库的地址 |
| 2 | **Supabase Secret Key**（`sb_secret_...`） | Settings → API Keys | 本机 MCP 直连数据库（仅你自己持有） |
| 3 | **数据库密码** | 建项目时自设（忘了可重置） | **仅初始化建表用一次**（路径 B；走路径 A 可不要） |
| 4 | **硅基流动 API Key**（`sk-...`） | cloud.siliconflow.cn 注册即送 | 生成记忆向量（bge-m3 永久免费） |

---

## Step 1 · 创建 Supabase 项目（3 分钟）

1. 打开 https://supabase.com/dashboard → **New project**
2. 随便起名（如 `my-memory`），**设置数据库密码并保存好**（凭据 3），区域建议 Singapore
3. 建好后在 Project Settings 里拿到：
   - **Project URL**（凭据 1）：`https://<你的ref>.supabase.co`
   - **Secret Key**（凭据 2）：Settings → API Keys → `sb_secret_...`

## Step 2 · 初始化数据库（二选一）

**路径 A（推荐，不需凭据 3）**：
Dashboard → 左侧 **SQL Editor** → New query → 把技能包里 `supabase/migrations/0001_init.sql` 和 `0002_enable_rls.sql` 的内容**依次完整粘贴**执行。

**路径 B（命令行）**：
```bash
export SUPABASE_ACCESS_TOKEN="<dashboard → account tokens 生成>"
export PROJECT_REF="<你的项目 ref，即 URL 里的那段>"
node scripts/apply-ddl-api.mjs   # 走管理 API，本机无 IPv6 也能用
```

> 两个 migration 都要跑：`0001` 建表和函数，`0002` 开启行级安全（不开的话你的 secret key 泄露 = 裸奔）。

## Step 3 · 注册硅基流动（2 分钟）

https://cloud.siliconflow.cn → 手机号/邮箱注册 → 「API 密钥」新建 → 复制 `sk-...`（凭据 4）。
注册送的额度 + bge-m3 免费档，个人记忆库用量基本零成本。

## Step 4 · 配置 MCP client（2 分钟）

把下面配置放进你的客户端，**四个凭据填自己的**：

**Claude Code**（`~/.claude.json` 或项目 `.mcp.json`）：

```json
{
  "mcpServers": {
    "external-memory": {
      "command": "node",
      "args": ["<技能包路径>/stdio/external-memory-mcp.mjs"],
      "env": {
        "SUPABASE_URL": "https://<你的ref>.supabase.co",
        "SUPABASE_SECRET_KEY": "sb_secret_...",
        "SILICONFLOW_API_KEY": "sk-...",
        "EM_OPERATOR": "human:<你的英文名>"
      }
    }
  }
}
```

**Cursor**（`~/.cursor/mcp.json`）：同构，`command/args/env` 字段一致。

`EM_OPERATOR` 说明：
- 个人用：`human:<你的名字>`（或不填，默认 `human:me`）
- 给 agent 用（按客户建记忆）：`agent:<agent名>:*`（全部客户）或 `agent:<agent名>:cust_a|cust_b`（白名单）

## Step 5 · 验证（1 分钟）

客户端里问一句：「帮我记住：我喜欢简洁直接的沟通风格（importance 8，preference）」——模型应调用 `record`。
新开一个会话问：「我的沟通风格偏好是什么？」——模型应先 `recall`/`wake` 再答出来。

命令行直测（可选）：

```bash
SUPABASE_URL=... SUPABASE_SECRET_KEY=... SILICONFLOW_API_KEY=... \
  node stdio/external-memory-mcp.mjs <<'EOF'
{"jsonrpc":"2.0","id":1,"method":"tools/list"}
EOF
```

## Step 6 · 打开记忆面板 PWA（可选，1 分钟）

在 `pwa/` 目录创建 `.env.local`，填入三个值（凭据 1 / 2 / 4）：

```
SUPABASE_URL=https://<你的ref>.supabase.co
SUPABASE_SECRET_KEY=sb_secret_...
SILICONFLOW_API_KEY=sk-...
```

然后启动：

```bash
cd pwa && npm install && npm run dev   # → http://localhost:5173
```

面板通过本机代理连接你的 Supabase，**密钥不经过浏览器**（Supabase 禁止 secret key 出现在浏览器环境，代理模式是它的官方推荐姿势）。如果打开看到「需要本机配置」指引页，说明 `.env.local` 没生效——检查文件名和三个值，重启 `npm run dev` 后点「重新检测」。

面板里能做什么：查看/搜索（与 MCP recall 同一套打分公式）/编辑/归档/删除你的记忆，查看 Story，编辑每个主体的 **profile 画像**（每次 wake 常驻加载的核心信息），粘贴原始素材并「提炼为记忆」（与 MCP record 同一套去重逻辑），一键整理（补向量/去重/归档/Story 聚合），导出 JSON。

**版本检测（可选）**：面板顶栏会显示当前版本号。想让面板提示「有新版」，在 `pwa/.env.local` 加一行：

```
VERSION_CHECK_URL=<一个返回 {"version":"0.2.0","url":"下载地址"} 的 URL>
```

**一键更新（可选）**：再加一行升级命令模板，顶栏角标就会变成「⬆ 一键更新」，点击后在本机命令行直接完成升级：

```
VERSION_UPDATE_CMD=curl -fsSL {url} -o /tmp/em-update.zip && rm -rf /tmp/em-update && unzip -q /tmp/em-update.zip -d /tmp/em-update && rsync -a --exclude '.env.local' /tmp/em-update/external-memory/ ../
```

- `{url}` `{version}` 是占位符，执行前自动替换为 version.json 里的值（已做注入防护，只接受 https 地址和纯数字版本号）
- 上面的模板假设命令在 `pwa/` 目录下执行（面板启动时就是这样）,`../` 即技能包根目录；`--exclude '.env.local'` 保证你的凭据不被覆盖
- 如果下载地址需要鉴权（比如私有技能），自己在模板里加 `-H "Authorization: ..."` 即可
- 更新完成后按提示重启 `npm run dev` 并强刷页面；如有新 migration，按 Step 2 补跑一次

不配这两项也能正常用，只是没有更新提醒和一键更新。

> 注意：PWA 与 MCP 是两条独立路径，连的是**同一个 Supabase 项目**——Agent 通过 MCP 写的记忆，PWA 里立即可见，反之亦然。

## 建议写进 Agent system prompt 的规约

```text
1. 会话开始先调用 wake 恢复记忆脉络。
2. 涉及我的历史偏好、过往事件时，先 recall 再回答；不确定时宁可调一次。
3. 出现值得长期记住的事实时调用 record（importance：10=长期约束 7-9=重要 4-6=一般 1-3=琐碎）。
4. record 返回 dedup=merged 是正常合并，无需重试。
```

## FAQ

**Q：数据库连接串 ENOTFOUND？**
免费档直连库是 IPv6-only。用路径 A（SQL Editor）初始化即可绕开；日常 MCP 调用走 HTTPS 不受影响。

**Q：embedding 调用失败？**
检查硅基流动 Key 是否有效、是否有 RPM 限速；失败的记忆会以 `embedding=null` 落库，下次 `consolidate` 自动补齐。

**Q：换电脑怎么办？**
凭据 1/2/4 不变，数据库在云端，新机器重新配一遍 Step 4 即可，记忆全在。

**Q：想给别人也用？**
各建各的 Supabase 项目（都免费），各用各的凭据——这就是自托管模式的意义：数据互不接触。

## 安全红线

- `sb_secret_...` 和硅基流动 Key 只放本机 MCP 配置的 env 里，**不发群、不进 git、不贴聊天**
- 怀疑泄露：Supabase Settings → API Keys → Rotate；硅基流动控制台 → 吊销重建
